# PersonaScope

합성 페르소나로 설문을 시뮬레이션하는 연구용 프로토타입입니다. 1차 사용자는 정책·여론 연구자입니다.

`legacy/`의 바닐라 JS 프로토타입(v4)을 기능·화면·문구·동작 그대로 React + Vite로 옮긴 버전입니다. 전환 작업의 배경과 규칙은 `CLAUDE.md`, 단계별 진행 기록은 `docs/MIGRATION_NOTES.md`를 참고하세요.

## 실행 방법

```
npm install
npm run dev      # 개발 서버
npm run build    # 프로덕션 빌드
npm run preview  # 빌드 결과 미리 보기
npm test         # Vitest (원본 대비 회귀 테스트 포함)
```

데이터는 브라우저 `localStorage`(키 `personascope-proto-v4`)에 저장됩니다. 처음 실행하면 예시 프로젝트가 자동으로 만들어지고, 프로젝트 목록 화면 아래의 "예시 데이터 다시 만들기"로 초기화할 수 있습니다.

원본 프로토타입은 `legacy/index.html`을 브라우저로 직접 열면 됩니다(서버 불필요).


## 원본과 달라진 점

기능·문구·화면 구성은 원본과 동일하게 유지했습니다. 다음은 전환 과정에서 생긴 구조적인 차이로, 동작에는 영향이 없습니다.

- **URL 기반 라우팅.** 원본은 전역 변수(`page`, `projectId` 등)로 화면을 전환했지만, 여기서는 React Router로 각 화면이 실제 경로를 가집니다. 그 덕분에 브라우저 뒤로 가기가 동작합니다(원본에는 없던 변화, 의도한 개선).
- **저장 형식은 동일.** `localStorage`의 키와 `{ projects: [...] }` 구조는 원본과 같아서, 원본에서 내보낸 저장 데이터를 그대로 붙여 넣어도 열립니다.
- **"렌더링 중 보정" 로직의 위치.** 원본은 화면을 그릴 때마다 전역 변수를 유효한 값으로 직접 고쳤습니다(예: 보고 있던 문항이 사라지면 첫 문항으로). React 버전에서는 이런 보정을 상태에 저장하지 않고, 화면에 표시할 때만 계산해서 씁니다. 동작 결과는 같습니다.
- **한글 입력 관련 코드 제거.** 원본은 전체를 다시 그리면서 입력 중이던 칸의 포커스·커서를 수동으로 복원하는 코드가 있었습니다. React는 같은 입력칸을 다시 만들지 않으므로 이 코드는 옮기지 않았고, 조합 끊김 없이 그대로 동작합니다.

## 기준값 바꾸는 곳

표본 경고 인원, 비교 최소 인원, 차이 강조 기준(%p), 페르소나 생성 인원 범위 등은 모두 `src/lib/config.js` 한 곳에서만 정의합니다. 값을 바꾸면 전체 화면에 반영됩니다.

```js
export const CONFIG = {
  MIN_GROUP: 30,      // 이 인원 미만인 집단은 표본 경고
  MIN_CELL: 5,        // 비교 구간 최소 인원 (미만이면 흐리게 + 순위 제외)
  HIGHLIGHT_PP: 10,   // 차이 강조 기준 (%p)
  MIN_PERSONAS: 10,
  MAX_PERSONAS: 500,
}
```

## 시연용 한계

실제 서비스가 아닌 시연용 프로토타입이라 다음과 같은 한계가 있습니다(`legacy/REVISION_NOTES.md`의 "시연용 한계" 참고).

- **응답은 시연 생성기가 만든 가짜 데이터**입니다. 문항마다 속성 몇 개에 따라 확률이 조금씩 달라질 뿐이라 차이 크기 자체에는 의미가 없습니다.
- **인원 추정치**는 조건 항목끼리 독립이라고 가정한 근사치입니다. 실제 원자료를 조회하지 않습니다.
- **서술형 조건**(취미, 페르소나 서술 등)은 시연 데이터에 서술 내용이 없어 집단 구성에 적용되지 않습니다.
- **직업 대분류**는 매핑 데이터가 없어 분석용 속성에서 제외했습니다.
- **인터뷰 답변은 템플릿**입니다. AI API와 연결되어 있지 않습니다.
- **다크 모드는 지원하지 않습니다.**
